1

Definición del Proyecto

Campo Descripción
Nombre del proyecto Sistema de Riego Hidropónico Inteligente
Problema que resuelve La falta de control automático sobre la humedad del cultivo hidropónico genera desperdicio de agua y riesgo de pérdida de plantas. El sistema monitorea continuamente y actúa sin intervención humana.
Sensores utilizados DHT22 — Temperatura y humedad ambiental (Pin 4)
Sensor capacitivo de humedad del suelo — Porcentaje de humedad del sustrato (Pin 35)
Actuador utilizado Bomba de agua — Controlada digitalmente vía transistor/relé (Pin 13). Activa/desactiva el riego según los umbrales definidos.
Dato que envía a internet Temperatura, humedad ambiental, porcentaje de humedad del suelo y estado de la bomba, publicados en formato JSON por Serial y visualizados en servidor web embebido.
Acción remota que permite Encender o apagar la bomba de agua remotamente desde un navegador web (ruta /toggle) o enviando el comando REGAR_ON / REGAR_OFF por Serial.
2

Responsabilidades del Firmware

initWiFi() / checkWiFi()

Conexión WiFi. Se encarga de conectar el ESP32 a la red y de reconectar automáticamente si se pierde la señal.

readSensors()

Lectura de sensores. Centraliza la lectura del DHT22 (temperatura y humedad) y del sensor de humedad del suelo, guardando los valores en variables globales.

controlActuators()

Control de actuadores. Evalúa los datos de los sensores y decide si activar o apagar la bomba, respetando los umbrales y el tiempo máximo de riego.

sendData()

Preparación y envío de datos. Actualiza la pantalla LCD con los valores actuales y envía los datos al puerto Serial en formato JSON.

handleCommands()

Recepción de comandos. Atiende las peticiones HTTP del servidor web embebido y los comandos de texto recibidos por Serial.

Estructura Inicial del Código

Arquitectura de llamadas en el firmware — cada bloque representa una responsabilidad separada:

setup()
Inicializa LCD · DHT22 · Bomba · WiFi · Servidor Web
↓
loop() — cada 2 segundos
↓
checkWiFi()
Mantiene conexión
handleCommands()
Web + Serial
readSensors()
DHT22 + Suelo
controlActuators()
Lógica de riego
sendData()
LCD + JSON Serial
// ── sketch.ino — Estructura modular ──────────────────────────────

// Librerías y configuración
#include <WiFi.h>  #include <WebServer.h>
#include <DHT.h>   #include <LiquidCrystal_I2C.h>

// Variables globales de sensores
float temperaturaVal, humedadAmbienteVal, humedadSueloVal;
bool  riegoActivo = false;

// ── MÓDULO 1: WiFi ───────────────────────────────────────────────
void initWiFi()    { /* conectar / reportar IP */ }
void checkWiFi()   { /* reconectar si cae */ }

// ── MÓDULO 2: Sensores ───────────────────────────────────────────
void readSensors() { /* DHT22 + sensor suelo → variables globales */ }

// ── MÓDULO 3: Actuadores ─────────────────────────────────────────
void controlActuators() { /* umbral → iniciarRiego() | detenerRiego() */ }

// ── MÓDULO 4: Datos ──────────────────────────────────────────────
void sendData()    { /* LCD + Serial JSON */ }

// ── MÓDULO 5: Comandos ───────────────────────────────────────────
void handleCommands() { /* server.handleClient() + Serial cmd */ }

// ── MAIN ──────────────────────────────────────────────────────────
void setup() {
    initWiFi();  configurarServidorWeb();
}
void loop() {
    checkWiFi();       handleCommands();
    readSensors();     // Responsabilidad 1: Leer
    controlActuators(); // Responsabilidad 2: Decidir
    sendData();        // Responsabilidad 3: Informar
}

5

Explicación de la Lógica

Función ¿Qué hace? ¿Qué parte del proyecto representa?
initWiFi() Intenta conectarse a la red WiFi con un tiempo límite de 10 segundos. Reporta la IP asignada o el error. Capa de Conectividad. Sin WiFi el sistema no puede recibir comandos ni (en un futuro) publicar en la nube.
checkWiFi() Se llama cada ciclo del loop; si detecta desconexión, llama a initWiFi() automáticamente. Resiliencia de red. Garantiza que el sistema no quede bloqueado por una caída momentánea del WiFi.
readSensors() Lee el DHT22 (temperatura y humedad ambiental) y el sensor capacitivo de suelo. Promedia 5 lecturas analógicas para mayor precisión y guarda los valores en variables globales. Capa de Percepción. Es la "vista" del sistema; sin datos correctos no hay decisión posible.
controlActuators() Compara la humedad del suelo con los umbrales definidos (HUMEDAD_SECA = 30%, HUMEDAD_HUMEDA = 70%). Activa la bomba cuando el suelo está seco y la apaga cuando está suficientemente húmedo o si supera el tiempo máximo de riego (10 s en simulación). Capa de Control / Lógica de Negocio. Es el "cerebro" del sistema; toma decisiones basadas en los datos.
sendData() Actualiza la pantalla LCD de 4 líneas con temperatura, humedad ambiente, humedad del suelo y estado de la bomba. Simultáneamente envía un objeto JSON completo por el puerto Serial. Capa de Telemetría. Prepara y expone el estado del sistema hacia el exterior (pantalla local y protocolo para nube futura).
handleCommands() Llama a server.handleClient() para atender peticiones HTTP del navegador y escucha el Serial en busca de comandos de texto (REGAR_ON / REGAR_OFF). Capa de Interacción Remota. Permite que un usuario o sistema externo controle el actuador a distancia.

¿Por qué se separó así el código?

  • Mantenimiento: Si se cambia el sensor DHT22 por un BME280, solo se modifica readSensors(), sin tocar el resto.
  • Debugging: Si el JSON no llega, se sabe que el problema está en sendData(), no en la lógica de riego.
  • Escalabilidad: Agregar MQTT para publicar en la nube solo requiere añadir código dentro de sendData().
  • Legibilidad: El loop() principal se lee como una lista de acciones claras: verificar → leer → decidir → informar.
